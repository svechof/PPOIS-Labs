## 2. Предметная область и границы (scope)

### 2.1 Что моделируют классы

**`tic_tac_toe::TicTacToe`** — игровое поле «Крестики-нолики» N×N для двух игроков с правилами игры: допустимость хода, чтение/запись клетки, определение победителя, ничьи и очерёдности хода.

**`polynomial::Polynomial`** — многочлен `p(x) = a₀ + a₁x + … + aₙxⁿ` от одной переменной с вещественными (`double`) коэффициентами, семантикой значения и арифметикой.

Классы независимы: нет общих типов, наследования, общего состояния и взаимных `#include` (5.2).

### 2.2 Соглашения: крестики-нолики

| Понятие | Соглашение |
|---|---|
| Фигуры | `Mark::kCross` (`X`), `Mark::kNought` (`O`), `Mark::kEmpty` (`.`) |
| Размер | N ∈ [`kMinBoardSize`=3, `kMaxBoardSize`=10]; по умолчанию `kDefaultBoardSize`=3 |
| Координаты | API: 0-based, `Position{row, col}`, строка 0 — верхняя. CLI: 1-based |
| Очерёдность | первым ходит `X`; `next_mark()` = `O`, если `X` на поле больше, чем `O`, иначе `X`. Класс очерёдность **не навязывает** (`place` не проверяет её) |
| **Правило победы** | игрок выигрывает, если **все N клеток** одной строки, одного столбца или одной из двух главных диагоналей заняты его фигурой (линия из N одинаковых символов) |
| Победитель | `winner()`: `kCross`, если у `X` есть линия; иначе `kNought`, если у `O`; иначе `kEmpty`. При двух линиях (возможно только через прямую запись `[]`) приоритет у `X` — детерминированно |
| Ничья | `is_draw()` = поле заполнено и победителя нет |
| Свойство правила | при N > 3 победа требует полной линии, ничьи вероятны; это следствие выбранного правила, а не ошибка |
| Два вида записи | `operator[]` (неконстантный) — низкоуровневая запись без проверки занятости (в т.ч. очистка клетки); `place` — ход по правилам |

### 2.3 Соглашения: многочлен

| Понятие | Соглашение |
|---|---|
| Коэффициенты | `double`; индекс = степень (`[0]` — свободный член), порядок возрастания |
| Степень | `degree()` — степень **нормализованного** многочлена; `kMaxDegree`=1000 |
| Пренебрежимое значение (negligible) | `\|c\| ≤ kCoefficientEpsilon` (`1e-9`, абсолютная погрешность) |
| Нормализация | старшие negligible-коэффициенты отбрасываются, пока размер > 1; если остался единственный negligible коэффициент — он заменяется на `+0.0` |
| Нулевой многочлен | `degree() == 0`, `[0] == 0.0`, `is_zero() == true`; степень нулевого многочлена по соглашению 0 |
| Задание | `Polynomial(degree, coefficients)`: `degree` — заявленная степень, массив из `degree+1` значений; после нормализации фактическая степень может быть меньше |
| Деление | деление «уголком» над ℝ; `/` возвращает **частное, остаток отбрасывается**; `deg(a) < deg(b)` → нулевой многочлен; делитель нулевой → исключение |
| Сравнение | `==` по нормализованным коэффициентам: равные степени и `\|aᵢ − bᵢ\| ≤ kCoefficientEpsilon` для всех `i` |
| Обоснование эпсилона | арифметика `double` накапливает ошибки округления: точное `==` делает `(a+b)−b == a` ложным для десятичных коэффициентов (`0.1`). Тот же порог в нормализации гарантирует согласованность «равенства» и «степени». Цена: `==` не транзитивно на границе порога; абсолютный порог не подходит для коэффициентов порядка ≥ 1e7 — это принятое ограничение (15) |
| Нечисловые значения | `NaN`/`±Inf` в коэффициентах недопустимы: конструкторы, `>>` и арифметика бросают `NonFiniteCoefficientError` |
| Запись через `[]` | степень вверх не растёт; запись negligible-значения в старший коэффициент уменьшает степень (3.2.3) |

## 3. Модель классов

Стиль имён (единый для проекта): типы — `PascalCase`; функции, методы, переменные, параметры — `snake_case`; приватные поля — `snake_case_` (суффикс `_`); константы и элементы `enum` — `kPascalCase`; пространства имён и файлы — `snake_case`. Проверяется `readability-identifier-naming` (12).

### 3.1 Класс «Крестики-нолики» — `tic_tac_toe::TicTacToe`

#### 3.1.1 Вспомогательные типы

| Тип | Определение | Файл |
|---|---|---|
| `enum class Mark : char` | `kEmpty = '.'`, `kCross = 'X'`, `kNought = 'O'` | `mark.h` |
| `char mark_to_char(Mark) noexcept` | значение → символ формата | `mark.h` |
| `Mark mark_from_char(char)` | символ → значение; иное → `InvalidMarkError` | `mark.h` |
| `struct Position { std::size_t row; std::size_t col; }` | агрегат, индексы 0-based; вызов `board[{1, 2}]` | `position.h` |

#### 3.1.2 Поля

| Поле | Тип | Назначение |
|---|---|---|
| `size_` | `std::size_t` | сторона поля N |
| `cells_` | `Mark*` | динамический массив из N·N клеток, построчно: индекс = `row * size_ + col` |

**Выбор представления.** Одномерный массив: одна аллокация (одно `new[]`/`delete[]`), смежная память, копирование одним `std::copy`, строгая гарантия присваивания достигается одной аллокацией до изменения состояния. Двумерный массив указателей потребовал бы N+1 аллокаций и частичной отмены при `bad_alloc`. Сырой массив (а не `std::vector`) выбран намеренно: класс демонстрирует правило трёх (3.1.3–3.1.5), которого требует `lab1.md`; многочлен использует `std::vector` (3.2.2).

**Инвариант класса `TicTacToe`:** `kMinBoardSize ≤ size_ ≤ kMaxBoardSize`; `cells_ != nullptr` и указывает на ровно `size_ * size_` инициализированных элементов; каждый элемент — один из трёх `Mark`; объект владеет массивом единолично. Баланс числа `X` и `O` и очерёдность **не** являются инвариантом (допускается прямая запись).

#### 3.1.3 Конструкторы

| Конструктор | Предусловия | Постусловия | Исключения |
|---|---|---|---|
| `TicTacToe()` | — | эквивалентно `TicTacToe(kDefaultBoardSize)`: поле 3×3, все клетки `kEmpty` | `std::bad_alloc` |
| `explicit TicTacToe(std::size_t size)` | `3 ≤ size ≤ 10` | `size() == size`, все клетки `kEmpty`; проверка размера **до** аллокации | `InvalidBoardSizeError` (размер вне диапазона); `std::bad_alloc` (утечки нет: `cells_` ещё не выделен) |
| `TicTacToe(const TicTacToe& other)` | `other` удовлетворяет инварианту | глубокая копия: `*this == other`, буферы разные | `std::bad_alloc` (утечки нет) |

#### 3.1.4 Деструктор

`~TicTacToe()` — **явный**, `noexcept`; выполняет `delete[] cells_`. Нужен, потому что класс владеет сырым массивом: неявный деструктор освободил бы только указатель. Двойное освобождение исключено: копирование глубокое, move отсутствует.

#### 3.1.5 Присваивание копированием

`TicTacToe& operator=(const TicTacToe& other)`

Семантика (порядок шагов фиксирован):

1. если `this == &other` — вернуть `*this` без действий (самоприсваивание безопасно);
2. выделить новый массив `other.size_ * other.size_` (единственная операция, способная бросить `std::bad_alloc`; при броске `*this` не изменён);
3. скопировать клетки (не бросает);
4. освободить старый массив, заменить `cells_` и `size_` (не бросает);
5. вернуть `*this`.

Гарантия: **строгая** (при исключении состояние `*this` не изменено). Допустимы разные размеры. Цепочка `a = b = c` корректна. Тест: T35–T38 (7.2).

#### 3.1.6 Move-семантика

**Не требуется и не объявляется.** Основания: `lab1.md` её не требует; наличие пользовательских деструктора и копирующих операций подавляет неявный move, поэтому «перемещение» корректно сводится к копированию; перемещённый объект с `cells_ == nullptr` нарушил бы инвариант; максимум 100 клеток — копирование дёшево. Это «правило трёх», а не «пяти». Проверка: `cppcoreguidelines-special-member-functions` с `AllowMissingMoveFunctions: true`.

#### 3.1.7 Публичный API

| Метод / оператор | Сигнатура | Назначение | Предусловия | Постусловия | Исключения |
|---|---|---|---|---|---|
| `size` | `[[nodiscard]] std::size_t size() const noexcept` | сторона поля | — | возвращает N | — |
| `can_place` | `[[nodiscard]] bool can_place(Position position, Mark mark) const noexcept` | можно ли поставить фигуру | — | `true` ⇔ позиция в поле ∧ клетка `kEmpty` ∧ `mark != kEmpty`; состояние не меняется | не бросает |
| `operator[]` (const) | `[[nodiscard]] const Mark& operator[](Position position) const` | чтение клетки | `position.row < N ∧ position.col < N` | возвращает ссылку на клетку | `PositionOutOfRangeError` |
| `operator[]` | `Mark& operator[](Position position)` | прямая запись: `board[{r, c}] = Mark::kCross;` | то же | ссылка на клетку; занятость и очерёдность **не проверяются**, допустима запись `kEmpty` | `PositionOutOfRangeError` |
| `place` | `void place(Position position, Mark mark)` | ход по правилам | `mark != kEmpty`, позиция в поле, клетка пуста | клетка = `mark`; при исключении поле не изменено | `InvalidMarkError`, `PositionOutOfRangeError`, `CellOccupiedError` (проверки в этом порядке) |
| `has_won` | `[[nodiscard]] bool has_won(Mark mark) const` | есть ли у игрока полная линия | `mark != kEmpty` | `true` ⇔ строка, столбец или диагональ целиком `mark` | `InvalidMarkError` |
| `winner` | `[[nodiscard]] Mark winner() const noexcept` | победитель | — | `kCross` / `kNought` / `kEmpty` (2.2) | не бросает |
| `is_full` | `[[nodiscard]] bool is_full() const noexcept` | нет пустых клеток | — | `true` ⇔ `count(kEmpty) == 0` | — |
| `is_draw` | `[[nodiscard]] bool is_draw() const noexcept` | ничья | — | `is_full() && winner() == kEmpty` | — |
| `count` | `[[nodiscard]] std::size_t count(Mark mark) const noexcept` | число клеток со значением | — | счётчик в [0, N²] | — |
| `next_mark` | `[[nodiscard]] Mark next_mark() const noexcept` | чей ход | — | `kNought`, если `count(X) > count(O)`, иначе `kCross` | — |
| `operator==` / `!=` | см. 3.1.9 | равенство | — | — | не бросает |
| `operator<<` / `>>` | см. 3.1.11 | текст | — | — | см. 3.1.11 |

Приватные члены: `std::size_t index_of(Position) const` (проверка границ, единая для обеих перегрузок `[]` и `place`), `void swap(TicTacToe&) noexcept`, помощники победы `is_row_owned_by(Mark, std::size_t)`, `is_column_owned_by(...)`, `is_main_diagonal_owned_by(Mark)`, `is_anti_diagonal_owned_by(Mark)` (каждый ≤ 20 строк, вложенность ≤ 2).

#### 3.1.8 Инкапсуляция

Оба поля `private`. Геттер один — `size()`. Указатель `cells_` и буфер наружу не отдаются; `operator[]` возвращает ссылку на **одну** клетку после проверки границ. Сеттера размера нет: размер — часть идентичности поля (смена размера = создание нового объекта). Правила игры (`can_place`, `place`, `has_won`, `winner`, `is_draw`, `next_mark`) находятся внутри класса (Information Expert), UI их не дублирует.

#### 3.1.9 Сравнение на равенство

`bool operator==(const TicTacToe& other) const noexcept` — `true` ⇔ `size() == other.size()` и все соответствующие клетки равны. Рефлексивно, симметрично, транзитивно. `bool operator!=(const TicTacToe& other) const noexcept` — `!(*this == other)`. Очерёдность и история ходов в равенство не входят.

#### 3.1.10 Операции варианта (подробно)

**Проверка возможности установки** — `can_place(position, mark)`.

| Вход | Результат |
|---|---|
| пустая клетка, `kCross` или `kNought` | `true` |
| занятая клетка | `false` |
| `mark == kEmpty` | `false` |
| `row >= N` или `col >= N` | `false` (не бросает: это предикат) |

**Получение значения** — `operator[] const`. `board[{0,0}]` и `board[{N-1,N-1}]` допустимы; `board[{N,0}]` или `board[{0,N}]` → `PositionOutOfRangeError("Position out of range: (N, 0) for board size N")`.

**Установка значения** — две операции:
- `board[{r, c}] = m` (неконстантный `operator[]`): граничная проверка есть, правила не проверяются. Назначение: настройка позиции, очистка клетки, тесты;
- `place({r, c}, m)`: полная проверка правил (порядок: `mark` → границы → занятость). Используется циклом партии в CLI.

**Проверка победы** — `has_won(mark)` и `winner()`. Линии: N строк, N столбцов, главная (`(i,i)`) и побочная (`(i,N−1−i)`) диагонали. Граничные случаи: пустое поле — победителя нет; N−1 фигур в линии — нет; линия `X X O` — нет; полное поле без линий — `is_draw()`; `has_won(kEmpty)` — исключение.

#### 3.1.11 Ввод-вывод

**Формат.** Первая лексема — размер N; далее ровно N лексем-строк по N символов. Лексемы разделяются любыми пробельными символами (пробел, `\n`, `\r`, `\t`).

```
board    = size , row , { row } ;            (* ровно N строк *)
size     = digit , { digit } ;               (* 1..18 цифр; значение ∈ [3, 10] *)
row      = cell , { cell } ;                 (* ровно N символов, без пробелов *)
cell     = "X" | "O" | "." ;                 (* регистр значим *)
```

Вывод `operator<<` (каноническая форма): `N`, перевод строки, затем N строк по N символов, каждая с `\n`. Пример для 3×3:

```
3
X.O
.X.
O.X
```

Ввод `operator>>` принимает и каноническую форму, и однострочную `3 X.O .X. O.X`.

**Политика ошибок: исключения, не `failbit`.** `operator>>` читает в **временный** объект и присваивает его цели только после полного успеха ⇒ при любой ошибке цель не изменена (строгая гарантия). Остаток потока после N+1 лексем не потребляется.

| Ввод | Результат |
|---|---|
| `3 X.O .X. O.X` | корректно |
| `4 ....  ....  ....  ....` | корректно |
| пустой поток | `InvalidBoardFormatError: Invalid board format: size is missing` |
| `abc`, `-3`, `3.5`, `1234567890123456789` | `InvalidBoardFormatError: ... size is not an integer: '<лексема>'` |
| `2 .. ..` или `11 ...` | `InvalidBoardSizeError: Invalid board size: 2 (allowed: 3..10)` |
| `3 X.O .X.` | `InvalidBoardFormatError: ... row 3 is missing` |
| `3 X.O .X O.X` | `InvalidBoardFormatError: ... row 2 has length 2, expected 3` |
| `3 X.O .Z. O.X` | `InvalidMarkError: Invalid mark: 'Z'` |
| `3 x.o ...` (нижний регистр) | `InvalidMarkError: Invalid mark: 'x'` |

Порядок проверок: лексема размера → диапазон размера → для каждой строки по порядку: наличие → длина → символы слева направо. Номера строк в сообщениях 1-based.

### 3.2 Класс «Многочлен» — `polynomial::Polynomial`

#### 3.2.1 Поля

| Поле | Тип | Назначение |
|---|---|---|
| `coefficients_` | `std::vector<double>` | коэффициенты по возрастанию степеней: `coefficients_[i]` — коэффициент при `xⁱ` |

Отдельного поля `degree_` **нет** (DRY): степень вычисляется из массива, поэтому рассогласование «степень ↔ размер» невозможно по построению.

**Инварианты класса `Polynomial`:**

| № | Инвариант |
|---|---|
| I1 | `1 ≤ coefficients_.size() ≤ kMaxDegree + 1` |
| I2 | `degree() == effective_size() − 1`, где `effective_size()` — позиция последнего не-negligible коэффициента + 1 (1, если такого нет) |
| I3 | Объект, созданный конструктором, копированием или арифметикой, хранится **канонически**: `coefficients_.size() == effective_size()`, а при `size() == 1` значение `c₀` либо не-negligible, либо ровно `+0.0` |
| I4 | все коэффициенты конечны (`std::isfinite`) |

Единственная операция, способная нарушить I3 и I4, — запись через неконстантный `operator[]`. Защита: старшие negligible-коэффициенты, оставшиеся после такой записи («мёртвые»), **недоступны через API и не влияют на поведение** (все операции читают только `[0, degree()]`); копирование их отбрасывает. Нефинитное значение через `[]` — нарушение предусловия вызывающего (I4 для записи через ссылку не проверяется); арифметика всё равно ловит его в результате (3.2.10).

**Выбор представления.** `std::vector<double>` вместо сырого массива: размер динамический (степень до 1000), исключения безопасны (`bad_alloc` при копировании не оставляет утечек), деструктор освобождения не требует. Ручное управление памятью уже продемонстрировано в `TicTacToe`; дублировать его в многочлене — лишний риск UB без новой учебной ценности.

#### 3.2.2 Конструкторы

| Конструктор | Предусловия | Постусловия | Исключения |
|---|---|---|---|
| `Polynomial()` | — | нулевой многочлен: `{0.0}`, `degree()==0`, `is_zero()` | `std::bad_alloc` |
| `Polynomial(int degree, const std::vector<double>& coefficients)` | `0 ≤ degree ≤ 1000`; `coefficients.size() == degree + 1`; все значения конечны | значение `Σ cᵢxⁱ`, нормализовано (I3); `this->degree() ≤ degree` | `InvalidDegreeError`, `CoefficientCountMismatchError`, `NonFiniteCoefficientError` (проверки в этом порядке); `std::bad_alloc` |
| `Polynomial(const Polynomial& other)` | — | `*this == other`; копируется только префикс `[0, other.degree()]` (канонический вид, I3); буферы независимы | `std::bad_alloc` |

Параметр `degree` имеет тип `int`, чтобы отрицательное значение можно было обнаружить и сообщить (`std::size_t` превратил бы `-1` в огромное положительное). Примеры: `Polynomial(2, {-5.0, 0.0, 3.0})` = `3x² − 5`; `Polynomial(3, {1.0, 2.0, 0.0, 0.0})` нормализуется до `1 + 2x`, `degree()==1`.

Приватная фабрика `static Polynomial from_raw(std::vector<double> raw)` — используется арифметикой: проверяет `raw.size() ≤ kMaxDegree+1` (иначе `InvalidDegreeError` со степенью `raw.size()−1`), конечность (`NonFiniteCoefficientError`), нормализует.

#### 3.2.3 Деструктор

`~Polynomial() = default;` — объявлен явно. `std::vector` освобождает память сам, пользовательская логика не нужна; явное `= default` документирует, что тройка копирование/присваивание/деструктор рассмотрена целиком.

**Совместимость с «правилом нуля».** Правило нуля советует не объявлять специальные функции вовсе. Здесь копирующие операции объявлены явно по **смысловой** причине, а не из церемонии: копия переносит только канонический префикс и тем самым гарантирует I3 (неявная копия `vector` скопировала бы «мёртвые» коэффициенты). Значение-семантика при этом сохранена (глубокая независимая копия, нет разделяемого состояния), и поведение не отличается от правила нуля с точки зрения клиента. Проверка: тесты P36–P41.

#### 3.2.4 Присваивание копированием

`Polynomial& operator=(const Polynomial& other)`

1. если `this == &other` — вернуть `*this`;
2. создать локальную копию `Polynomial copy(other)` (единственная операция, способная бросить `std::bad_alloc`);
3. обменять содержимое `*this` и `copy` приватным `swap(Polynomial&) noexcept`;
4. вернуть `*this` (старое содержимое уничтожается вместе с `copy`).

Гарантия: **строгая**. Разные степени допустимы; цепочка `a = b = c` корректна.

#### 3.2.5 Инкапсуляция

Поле `private`. Наружу: `degree()` (геттер значения), `operator[]` (доступ к одному коэффициенту после проверки границ), `is_zero()`. Нет `data()`, `begin()/end()`, ссылки на вектор и сеттера степени: иначе клиент мог бы обойти нормализацию и границы. Степень и массив согласуются только внутри класса.

#### 3.2.6 Move-семантика

**Не требуется и не объявляется.** (1) `lab1.md` её не требует; (2) стандартный `= default` оставил бы перемещённый объект с пустым вектором, что нарушает I1; ручной move, оставляющий `{0.0}`, должен выделять память и не может быть `noexcept` — лишняя сложность; (3) объект ≤ 1001 `double`; возврат результата арифметики не копирует благодаря guaranteed copy elision (C++17). Явное объявление копирующих операций подавляет неявный move, и «перемещение» сводится к копированию — корректно.

#### 3.2.7 Публичный API

| Метод / оператор | Сигнатура | Назначение | Предусловия | Постусловия | Исключения |
|---|---|---|---|---|---|
| `degree` | `[[nodiscard]] std::size_t degree() const noexcept` | степень | — | `effective_size() − 1` | — |
| `is_zero` | `[[nodiscard]] bool is_zero() const noexcept` | нулевой ли многочлен | — | `degree()==0 ∧ \|c₀\| ≤ ε` | — |
| `operator[]` (const) | `[[nodiscard]] const double& operator[](std::size_t power) const` | чтение коэффициента при `x^power` | `power ≤ degree()` | ссылка на коэффициент | `CoefficientIndexError` |
| `operator[]` | `double& operator[](std::size_t power)` | запись коэффициента | `power ≤ degree()`; записываемое значение конечно | ссылка; степень вверх не растёт; запись negligible в старший коэффициент уменьшает `degree()` | `CoefficientIndexError` |
| `operator()` | `[[nodiscard]] double operator()(double point) const noexcept` | значение `p(point)` по схеме Горнера | — | вычислено; переполнение даёт `±Inf` по IEEE 754 (не исключение) | — |
| `operator+=` | `Polynomial& operator+=(const Polynomial& rhs)` | сложение | — | `*this = *this + rhs`, нормализовано | `NonFiniteCoefficientError`, `bad_alloc` |
| `operator-=` | `Polynomial& operator-=(const Polynomial& rhs)` | вычитание | — | аналогично | то же |
| `operator*=` | `Polynomial& operator*=(const Polynomial& rhs)` | произведение | `degree() + rhs.degree() ≤ 1000` | свёртка коэффициентов | `InvalidDegreeError`, `NonFiniteCoefficientError`, `bad_alloc` |
| `operator/=` | `Polynomial& operator/=(const Polynomial& rhs)` | частное | `!rhs.is_zero()` | `*this` = частное, остаток отброшен | `DivisionByZeroPolynomialError`, `NonFiniteCoefficientError`, `bad_alloc` |
| `operator+` `-` `*` `/` | `Polynomial operator+(Polynomial lhs, const Polynomial& rhs)` и т.д. (свободные, не friend) | значение-версии | как у составных | `lhs op= rhs; return lhs;` | как у составных |
| `operator==` / `!=` | см. 3.2.9 | равенство | — | — | не бросает |
| `operator<<` / `>>` | см. 3.2.11 | текст | — | — | см. 3.2.11 |

Все составные операции дают **строгую гарантию**: результат строится во временном векторе, проверяется, и только затем обменивается с `coefficients_`. Aliasing безопасен: `p += p`, `p -= p` (ноль), `p *= p` (квадрат), `p /= p` (константа 1 при `!is_zero()`).

Приватные члены: `effective_size() const noexcept`, `coefficient_or_zero(std::size_t power) const noexcept` (0.0 за пределами степени), `static void normalize(std::vector<double>&) noexcept`, `static void require_finite(const std::vector<double>&)`, `void swap(Polynomial&) noexcept`, `from_raw` (3.2.2). Унарный минус не требуется (YAGNI).

#### 3.2.8 Операции варианта (подробно)

**Получение коэффициентов `[]`.** `p[0]` — свободный член, `p[p.degree()]` — старший (ненулевой для `degree()>0`). `p[p.degree()+1]` → `CoefficientIndexError("Coefficient index out of range: <i> (degree is <d>)")`. Для нулевого многочлена допустим только `p[0]`. Неконстантная перегрузка пишет значение: `p[1] = 4.0;` меняет коэффициент; `p[2] = 0.0` для многочлена степени 2 уменьшает `degree()` до 1, после чего `p[2]` бросает исключение (коэффициенты выше степени не существуют).

**Вычисление `operator()`.** Схема Горнера по `[0, degree()]`. `Polynomial(2, {-5, 0, 3})(2.0) == 7.0`; `Polynomial()(x) == 0.0` для любого `x`; константный многочлен возвращает `c₀`.

**Сложение/вычитание.** Результирующий размер `max(deg a, deg b) + 1`, недостающие коэффициенты — 0; затем нормализация (старшие члены могут сократиться: `(x² + x) + (−x²) = x`, `p − p = 0`).

**Произведение.** Свёртка: `cₖ = Σ aᵢ·bₖ₋ᵢ`, размер `deg a + deg b + 1`; если `deg a + deg b > kMaxDegree` → `InvalidDegreeError` (операнды не изменены). Умножение на нулевой многочлен даёт нулевой.

**Деление (`/`, `/=`).** Алгоритм: деление «уголком» над ℝ. Пусть `a` степени `m`, `b` степени `n`, старший коэффициент `b` — `bₙ`.

1. `b` нулевой → `DivisionByZeroPolynomialError("Division by zero polynomial")`;
2. `m < n` → результат нулевой многочлен (не исключение);
3. рабочая копия `r` коэффициентов `a`; для `k` от `m−n` до 0: `qₖ = r[n+k] / bₙ`; для всех `j ∈ [0, n]`: `r[j+k] −= qₖ·bⱼ`;
4. частное `q` (размер `m−n+1`) нормализуется и проверяется на конечность; **остаток `r[0..n−1]` отбрасывается** (решение зафиксировано, публичного API остатка нет).

Контрольные значения для тестов: `(x² − 1) / (x − 1) = x + 1`; `(x³ − 6x² + 11x − 6) / (x − 1) = x² − 5x + 6`; `(x²+1) / x = x` (остаток 1 отброшен); `(x³ + 2x + 1) / (x² + 1) = x` (остаток `x+1` отброшен); `(x+1) / x² = 0`; `0 / b = 0`; `(2x²+4) / 2 = x² + 2`. Делитель, у которого все коэффициенты negligible, считается нулевым.

Для соблюдения «метод ≤ 20 строк» алгоритм разбит на приватные шаги (`divide_step`, `subtract_scaled_divisor`, свёртка `convolve`) — внутри анонимного пространства имён `polynomial_arithmetic.cpp`.

#### 3.2.9 Сравнение на равенство

`bool operator==(const Polynomial& other) const noexcept` — `true` ⇔ `degree() == other.degree()` и `|aᵢ − bᵢ| ≤ kCoefficientEpsilon` для всех `i ∈ [0, degree()]`. `!=` — отрицание. Следствия: `Polynomial(3,{1,2,0,0}) == Polynomial(1,{1,2})`; разность `5e-10` — равны; `2e-9` — не равны; `Polynomial()` равен `Polynomial(0,{1e-12})`. Рефлексивно и симметрично; транзитивность на границе порога не гарантируется (2.3, 15).

#### 3.2.10 Исключения-политики арифметики

После вычисления результата каждая арифметическая операция проверяет конечность коэффициентов; при `Inf/NaN` бросает `NonFiniteCoefficientError("Non-finite coefficient at power <i>")` (первый найденный индекс), операнды не меняются.

#### 3.2.11 Ввод-вывод

**Выбранный формат — список коэффициентов** (машинный, без потерь, простой разбор): `degree c₀ c₁ … c_degree`. Алгебраическая запись `3x^2 - 5` — только форма отображения в CLI (6.4), домен её не разбирает.

```
polynomial  = degree , { ws , coefficient } ;      (* ровно degree+1 коэффициентов *)
degree      = [ "+" | "-" ] , digit , { digit } ;  (* до 9 цифр; допустимое значение 0..1000 *)
coefficient = [ "+" | "-" ] , ( digits [ "." [ digits ] ] | "." digits ) , [ ( "e" | "E" ) , [ "+" | "-" ] , digits ] ;
digits      = digit , { digit } ;
ws          = " " | "\t" | "\n" | "\r" ;           (* любое число *)
```

Запрещены: `nan`, `inf`, шестнадцатеричная запись, запятая как десятичный разделитель.

**Вывод `operator<<`**: `degree()`, затем коэффициенты `[0..degree()]`, разделитель — один пробел, без пробела в конце и без `\n`. Число выводится в `defaultfloat` с точностью `kOutputPrecision` (17 значащих цифр ⇒ точный round-trip). Флаги и точность потока **восстанавливаются** после вывода. Примеры: `Polynomial(2,{-5,0,3})` → `2 -5 0 3`; нулевой → `0 0`; `Polynomial(1,{0.1,2})` → `1 0.10000000000000001 2`.

**Ввод `operator>>`**: читает лексемы; строгая гарантия (цель обновляется после полного успеха, как в 3.1.11); степень проверяется **сразу** после разбора, до чтения коэффициентов; результат нормализуется.

| Ввод | Результат |
|---|---|
| `2 -5 0 3`, `+1 2 3`, `0 7`, `1 .5 -1e2`, `1 5. 2` | корректно |
| `3 1 2 0 0` | корректно, `degree()==1` (нормализация) |
| пустой поток | `InvalidPolynomialFormatError: Invalid polynomial format: degree is missing` |
| `x`, `1.5 1 2`, `1e2 1 2` | `... degree is not an integer: '<лексема>'` |
| `-1 0`, `1001 ...` | `InvalidDegreeError: Invalid degree: -1 (allowed: 0..1000)`; коэффициенты не читаются |
| `2 1 2` | `... expected 3 coefficients, got 2` |
| `1 a 2`, `1 1e 2`, `1 0x10 2`, `1 nan 2`, `1 inf 2`, `1 1,5 2` | `... coefficient is not a number: '<лексема>'` |
| `1 1e999 2` | `NonFiniteCoefficientError` (переполнение при конвертации) |

Пример round-trip: `os << p; is >> q;` ⇒ `p == q` точно, для любых конечных `p`.

#### 3.2.12 Разделение объявления и реализации

| Файл | Содержимое |
|---|---|
| `include/polynomial/constants.h` | `kMaxDegree`, `kCoefficientEpsilon`, `kOutputPrecision` |
| `include/polynomial/exceptions.h` | иерархия исключений (3.2.13) |
| `include/polynomial/polynomial.h` | класс, свободные арифметические операторы, `operator<<`/`>>`; только объявления + Doxygen |
| `src/polynomial/exceptions.cpp` | конструкторы исключений, формирование сообщений |

| `src/polynomial/polynomial_arithmetic.cpp` | `+= -= *= /=` и свободные `+ - * /` |
| `src/polynomial/polynomial_io.cpp` | `operator<<`, `operator>>`, разбор лексем |

#### 3.2.13 Исключения

```
std::runtime_error
└── PolynomialError                       (базовый для домена)
    ├── InvalidDegreeError
    ├── CoefficientCountMismatchError
    ├── NonFiniteCoefficientError
    ├── CoefficientIndexError
    ├── DivisionByZeroPolynomialError
    └── InvalidPolynomialFormatError
```

| Класс | Когда бросается | `what()` |
|---|---|---|
| `InvalidDegreeError` | конструктор, `>>`: степень < 0 или > 1000; `*`/`*=`: степень результата > 1000 | `Invalid degree: <d> (allowed: 0..1000)` |
| `CoefficientCountMismatchError` | конструктор: `size() != degree+1` | `Coefficient count mismatch: degree <d> requires <d+1> coefficients, got <k>` |
| `NonFiniteCoefficientError` | конструктор, `>>`, результат арифметики: `NaN`/`±Inf` | `Non-finite coefficient at power <i>` |
| `CoefficientIndexError` | `operator[]` (обе): `power > degree()` | `Coefficient index out of range: <i> (degree is <d>)` |
| `DivisionByZeroPolynomialError` | `/`, `/=` при нулевом делителе | `Division by zero polynomial` |
| `InvalidPolynomialFormatError` | `>>`: нет степени, не число, мало коэффициентов, не-число | `Invalid polynomial format: <детали>` (3.2.11) |

### 5.2 Правила зависимостей (ключевое архитектурное требование)

| Модуль | Может зависеть от | Не может зависеть от |
|---|---|---|
| `tic_tac_toe` | стандартная библиотека | `polynomial`, `cli`, `std::cin/cout/cerr` |
| `polynomial` | стандартная библиотека | `tic_tac_toe`, `cli`, `std::cin/cout/cerr` |
| `cli` (`lab1_cli_lib`) | **публичные** заголовки обоих доменов, стандартная библиотека | внутренние поля доменов (их нет в публичном API) |
| `tests/tic_tac_toe` | `tic_tac_toe`, GoogleTest | `polynomial`, `cli` |
| `tests/polynomial` | `polynomial`, GoogleTest | `tic_tac_toe`, `cli` |
| `tests/cli` | `lab1_cli_lib`, оба домена, GoogleTest | — |

Домены не наследуются друг от друга, не делят типы, константы и состояние; иерархии исключений раздельные (`TicTacToeError`, `PolynomialError`), общего базового класса, кроме `std::runtime_error`, нет. Домен знает про потоки только как параметры `std::istream&`/`std::ostream&` операторов.

**Как это проверяется:**
1. CMake: `target_link_libraries(tic_tac_toe PUBLIC)` и `(polynomial PUBLIC)` не содержат проектных библиотек; каждая цель собирается отдельно (`cmake --build build --target tic_tac_toe`).
2. `scripts/check_independence.sh` (запускается в CI): `grep` не находит `#include "polynomial/` в `include/tic_tac_toe`, `src/tic_tac_toe`, `tests/tic_tac_toe`; симметрично для `polynomial`; ни одного `#include "cli/` и `std::cin|std::cout|std::cerr` в доменах.
3. Самодостаточность заголовков: тесты T54/P50 подключают каждый заголовок в одиночку.

### 5.3 Слои CLI

`main.cpp` создаёт `cli::Application(std::cin, std::cout)` и вызывает `run()`. `Application` → `TicTacToeMenu` / `PolynomialMenu` → `Console` (чтение строки, целого в диапазоне, символа; печать) и `BoardView` / `PolynomialView` (отображение). Потоки **внедряются**, а не берутся глобально — поэтому CLI тестируется через `std::istringstream`/`std::ostringstream` (IoC, DIP). CLI обращается к доменам только через публичный API (`size()`, `operator[]`, `degree()`, …).

### 5.4 Общий код

Модуля `common/` **нет**. Дублируется только разбор лексем (≈10 строк в каждом домене); общий модуль связал бы домены третьей зависимостью, что противоречит 5.2, и нарушил бы KISS/YAGNI. Если дублирование превысит ~15 строк — выносить в `include/common/` отдельным PR с обоснованием.

### 5.5 Принципы SOLID / GRASP

| Принцип | Применение |
|---|---|
| SRP | `TicTacToe` — поле и правила; ввод-вывод — отдельные функции и файл; отображение — в `cli/`; исключения — отдельный заголовок |

## 6. CLI-интерфейс

### 6.1 Общая схема

Одна программа `lab1_cli`. Запуск: `./build/bin/lab1_cli`. Ввод построчный (`std::getline`), числа разбираются из строки; пользовательские строки (UTF-8) — константы в `messages.h`.

```
=== Лабораторная работа №1 ===
1. Крестики-нолики
2. Многочлен от одной переменной
0. Выход
Ваш выбор:
```

**Обработка ошибок (общая для всех меню):**

| Ситуация | Поведение |
|---|---|
| Нечисловой/внеменюшный ввод | сообщение `Некорректный ввод`, повторный показ меню |
| Исключение домена (`TicTacToeError`, `PolynomialError`) | сообщение `Ошибка: <what()>`, возврат в меню, состояние домена не изменено (строгая гарантия) |
| Конец входного потока (EOF) | корректный выход, код 0 |
| Иное `std::exception` | сообщение `Внутренняя ошибка: <what()>`, код возврата 1 |

Падений (неперехваченных исключений, UB) быть не должно.

### 6.2 Крестики-нолики

## 7. Тестирование

### 7.1 Общие решения

| Параметр | Решение |
|---|---|
| Фреймворк | **GoogleTest** `v1.14.0` (через CMake `FetchContent`). Причины: стандарт де-факто, интеграция с CTest (`gtest_discover_tests`), параметризованные тесты для таблиц ввода, читаемые сообщения об ошибках. Catch2 равноценен, но не даёт преимуществ |
| Запуск без IDE | `ctest --test-dir build --output-on-failure` либо `./build/bin/<domain>_tests` |
| Раздельные бинарники | `tic_tac_toe_tests`, `polynomial_tests`, `cli_tests` — домены тестируются независимо |
| Детерминизм | никаких случайных данных без фиксированного seed; тесты не зависят от порядка |
| Проверка исключений | тип **и** текст: `EXPECT_THROW` + отдельная проверка `what()` (через вспомогательный макрос `EXPECT_THROW_WITH_MESSAGE`) |
| Нормы | тесты — не «магические числа»: тестовые данные допустимы (`tests/.clang-tidy` отключает только `readability-magic-numbers`; остальные проверки действуют) |

**Покрытие (строчное) — условие приёмки, строго `> 90 %`:**

| Область | Что измеряется | Порог (падение CI при ≤ 90.0) |
|---|---|---|
| Домен 1 | `include/tic_tac_toe/**`, `src/tic_tac_toe/**` | `> 90 %` |
| Домен 2 | `include/polynomial/**`, `src/polynomial/**` | `> 90 %` |
| Проект в целом | оба домена + `cli/src/**`; исключены `cli/main.cpp`, `tests/**`, `_deps/**` | `> 90 %` |

Внутренняя цель — ≥ 95 %. Ветвевое покрытие (`--exclude-throw-branches`) публикуется в отчёте как справочное. Инструмент — `gcov` + `gcovr`; команды в разделе 9, шаги CI — в разделе 10.

| `pull_request` | в `main` | jobs до `smoke-clean-container` включительно |
| Фильтр путей | `lab1/**`, `.github/workflows/lab1.yml` (для push тегов фильтр путей не применяется) | остальные lab-папки CI lab1 не запускают |

Права: по умолчанию `contents: read`; `release` получает `contents: write`. Все `run`-шаги по умолчанию в `working-directory: lab1`. Отмена устаревших запусков: `concurrency: group: lab1-${{ github.ref }}, cancel-in-progress: true`.

### 10.5 Независимость артефакта от среды разработки

Бинарник собирается со `-static` (libstdc++ и libc внутри), поэтому не зависит от версии glibc/libstdc++ раннера. Два независимых подтверждения: (1) `smoke-clean-container` — чистый контейнер `ubuntu:22.04` без инструментов сборки запускает **собранный в CI** артефакт; (2) `verify-release` — тот же контейнер скачивает файл именно **из Releases** и сверяет SHA-256. Демонстрация обоих доменов — сценарии S1–S3 (6.5), эталоны сравниваются построчно.

### 10.6 Релизный процесс

Релиз создаётся тегом `v1.0.0` на коммите в `main` (после слияния PR); версия — SemVer. CI на `main` без тега публикует только артефакты job’ов (без Releases).

| Слияние | через PR после одобрения; сообщение результирующего коммита тоже осмысленное |

### 11.4 Сообщения коммитов

Формат Conventional Commits: `<type>(<scope>): <что и зачем>`; типы `feat`, `fix`, `test`, `docs`, `refactor`, `ci`, `build`, `chore`. Язык — русский или английский, не смешивать внутри сообщения. Тело — при необходимости: почему.

Примеры допустимых: `feat(tic-tac-toe): add rule-of-three for board with strong assignment`; `test(polynomial): cover division by zero and lower-degree dividend`; `ci: fail pipeline when per-domain coverage is 90% or less`.

Запрещены: `fix`, `fix 1`, `final fix`, `wip`, `asdf`, `commit N`, пустые и односложные сообщения. Проверка: ревью PR + `commitlint`-подобная проверка шаблона `^(feat|fix|test|docs|refactor|ci|build|chore)(\(.+\))?: .{10,}` в job `format-lint` (на PR по `git log origin/main..HEAD`).

### 15.2 Допущения

1. Кодировка исходников и вывода — UTF-8; терминал её поддерживает.
2. Разделители в потоках — любые пробельные символы (3.1.11, 3.2.11); десятичный разделитель — точка (локаль `C`).
3. CI — `ubuntu-latest`; компиляторы `g++ ≥ 11` и `clang++ ≥ 14` из apt; архитектура x86-64.
4. Репозиторий доступен для скачивания релизов без авторизации (иначе `verify-release` использует `gh release download` с `GITHUB_TOKEN`).
5. Требуемый размер поля [3, 10] и степень ≤ 1000 приемлемы как «произвольные» (константы изменяемы в одном месте).
6. Преподаватель допускает реализацию двух вариантов вместо одного.
7. `questions.md` совпадает по составу с `questions_help.md`.
